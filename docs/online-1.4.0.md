# 在线改造 1.4.0：需求基线与实现

已由用户确认。后端环境：twentyfour-d6g4wbv3c4f226753（上海，体验版）。

## 帐号与数据
- 本地练习：不需要帐号，不调用云端；旧帐号统计与错题本合并到练习记录，迁移幂等，保留原始数据和备份。
- 在线：只用微信身份，无密码；昵称/头像可使用微信选择能力或自行填写/上传。微信不会静默提供真实昵称头像。
- 历史答题记录、错题本、设置云端保存；登录换设备后分页恢复全部记录。
- 排行榜本人全名，其他人首字符加一个星号，所有人无头像。云端响应不包含其他人的用户ID、全名或头像。

## 成绩规则
- 两个独立榜单：成功率、单题最快用时；每个均有总榜和本周榜。
- 成功率总榜累计13题，本周榜本周13题；最快榜只需对应期间答对1题。
- Basic/Pro以及两种JQK规则合并排名。同指标严格相等并列1、1、3；成功率比较原始分数而非显示舍入值。
- 北京时间周一00:00切周。总榜连续7×24小时无新成绩不展示；完成正常题（含跳过/答案）恢复，保留历史数据和原上榜门槛。
- 前100名（第100名并列者同时展示），固定展示本人名次、成绩或不符合条件的原因。
- 错答只提示，保留当前题及起始时间，不计入历史、失败数或错题本；Basic 最终运算与 Pro 提交采用相同规则。
- 答对才记成功；跳过/看答案记失败；每题只结算一次。120 秒只提示用时较长，继续计时，超过 120 秒仍可答对。
- 客户端判定成功立即冻结显示，0.5 秒后进入下一题流程。上一题云端结算未完成时显示加载，确认完成后才向服务器请求下一题，避免覆盖单题会话；新题渲染就绪才启动计时。
- 主动离开/重开未完成题不统计；断网当题中止，只能本地练习；联网需重新登录开局，不补传离线成绩。
- 切后台仍按时间戳计时；错题重复练习只更新掌握进度，不计在线统计和排名。
- 成功算式云端再次验证，须正确使用4张牌；无效答案返回 `settled:false` 并保持会话 open。旧客户端 timeout 请求也只返回未结算。
- 牌由云端发出；在线历史/排行榜仍采用服务器发题至接收结算的时间，客户端伪造用时无效。页面显示与本地练习采用客户端就绪至判定的时间；两者可能存在网络差值，动画和结算回包等待均不延长页面时间。

## 数据结构
| 集合 | 内容 | 访问 |
|---|---|---|
| tf24_users | 昵称、头像引用、偏好、错题账本、牌堆 | 仅云函数/管理员 |
| tf24_sessions | 每用户当前题、云端开始时间、结算状态与幂等结果 | 仅云函数/管理员 |
| tf24_rounds | 完整的有效正常答题记录 | 仅云函数/管理员 |
| tf24_stats | 每用户总计/按周计数、最快用时、最近成绩时间 | 仅云函数/管理员 |

使用事务同时结算题目、历史、总榜/周榜和错题本。客户端只能调用云函数，不能直写集合。
每帐号同时仅保留一题在线会话；其他设备重新开局会使旧题失效，避免并行会话覆盖。
头像保存在云存储。昵称、头像保存时通过微信内容安全接口检查，需配置相应OpenAPI权限。

## 部署步骤与交付门槛
1. 确认本环境已关联小程序 wx58faf81d08ca037c。腾讯云创建环境还需微信公众平台帐号关联，参照 https://docs.cloudbase.net/quick-start/create-env 。
2. 用 scripts/cloudbase-admin.py 发起设备授权并保存到仓库以外私有目录。禁止提交令牌/私钥。
3. 在 cloudfunctions/tf24 下运行 npm ci --ignore-scripts，再运行部署脚本；四个集合全部ADMINONLY。
4. 检查云函数运行状态、OpenAPI内容安全权限、头像存储访问规则（本人写）、微信真实登录、重复结算、断网/后台切换、换设备恢复。
5. 通过后合入main，既有WeChat Mini Program工作流构建、上传开发版1.4.0并生成预览二维码。
6. 审核和正式上线仍由用户另行启动。本PR不触发正式发布。

## 尚需云端联调确认
