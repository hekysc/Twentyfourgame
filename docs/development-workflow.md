# 项目标准开发流程

本文件定义本项目日常功能开发的默认交付流程。开始开发前先阅读本文件、`AGENTS.md`、`README.md` 和相关功能文档；发现现有工作流与本文不一致时，以实际 GitHub Actions 配置为准，并同步修正文档。

## 适用范围

适用于日常功能、缺陷修复和微信小程序开发版验证。开发版上传不等于提交审核或正式发布；正式发布仍按本文末尾的独立发布流程执行。

## 日常开发

1. **确认基线与范围**：检查当前 `main`、未完成任务、相关代码和线上环境配置。确认本次要解决的问题、验收行为及是否涉及 CloudBase、登录或数据结构。
2. **隔离修改**：从最新 `main` 建立本次功能分支。聚焦一个可审查的改动范围，保留用户已有数据兼容与迁移要求；不要手改 `unpackage/` 或构建产物。
3. **实现并自测**：按改动风险运行对应检查。涉及游戏/在线规则时运行 `npm test`；微信小程序变更至少运行 `npm run build:mp-weixin` 并检查构建输出。涉及 UI 时检查关键页面与交互；涉及后端时验证函数、集合权限和云端数据流程。
4. **云端变更先验证**：若改动 CloudBase 函数、集合、索引、权限或环境配置，先确认目标环境 ID 和 GitHub Actions Secrets 指向正确环境，再部署并验证云端。当前环境 ID 为 `twentyfour-d6g4wbv3c4f226753`；部署凭据只从 GitHub Actions Secrets 读取，不写入仓库、日志或聊天。当前 CloudBase 部署工作流定义在 `.github/workflows/cloudbase-deploy.yml`：main 上云函数/部署脚本变更会部署，本次 `fix/round-settlement-flow` 分支也允许先行部署验证；部署前运行后端规则测试，部署后检查函数和集合状态。若工作流不在本次分支/目标分支中，先按项目现行安全配置完成部署，或在交付说明中明确阻塞，不能声称云端已部署。
5. **创建 PR 并检查**：提交代码并创建指向 `main` 的 PR。等待 PR 检查通过，查看构建、测试与改动差异；失败时修复并重新运行。PR 阶段只构建和验证，不上传微信开发版。
6. **合并并交付开发版**：在本次任务授权范围内将通过检查的 PR 合并到 `main`。涉及微信小程序源码/构建路径的 main push 会自动触发 **WeChat Mini Program** 工作流：构建、测试、上传微信开发版并生成预览二维码。版本号取 `package.json` 的版本；不要为普通开发自动改版本号。纯文档改动不会触发微信上传。
7. **取回二维码并汇报**：确认工作流的 build、upload 和 preview 步骤全部成功；取回 QR Artifact（`wechat-preview-qr-<version>`，保留 7 天），直接提供二维码或可访问的下载链接，并附 GitHub Actions 运行链接、开发版本、测试结果和必要的扫码说明。工作流失败时先排查并重跑，不得把未上传成功说成已交付。
8. **记录结果**：将有持续价值的架构/环境变化写入对应文档；完成的开发事项追加到 `work_continue.md` 的完成记录。不要把敏感凭据或个人信息写入记录。

## CloudBase 与微信开发版的边界

- 本地练习、登录在线状态和排行榜相关变更可能同时影响前端、CloudBase 云函数与数据库；确认三者版本/契约一致后再交付。
- CloudBase 部署与微信小程序上传是两条独立链路。云端部署成功不能替代小程序构建上传；小程序二维码成功也不能证明云端部署完成。
- 只有实际部署到目标环境并通过状态/功能验证后，才能报告云端部署完成。没有后端变更时跳过 CloudBase 部署。
- Secrets 不可读回，也不可复制到代码或文档；只验证 workflow 使用结果，不回显凭据。
- 开发版二维码用于体验测试。微信审核、正式发布以及其他不可逆线上操作需要单独明确的发布指令。

## 工作流事实来源

- 微信构建、上传和二维码：`.github/workflows/wechat-release.yml` 与 [微信小程序构建与上传流程](wechat-release.md)。
- CloudBase 部署：`.github/workflows/cloudbase-deploy.yml` 及对应分支上的部署配置。
- 项目规范及完成日志：`AGENTS.md`、`work_continue.md`。

## 正式发布

正式发布与日常开发版交付分开处理。只有收到明确的正式发布指令后，才按 [微信小程序构建与上传流程](wechat-release.md) 中的 Formal Release Preparation 流程准备候选版本；准备候选不代表提交审核或上线，线上发布需再次取得明确指令。
